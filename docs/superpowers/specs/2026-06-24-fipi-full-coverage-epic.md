по физике, строго по Спецификации и Кодификатору ФИПИ ОГЭ-2026: 7 комплектов
оборудования, полный перечень опытов каждого. Каждый опыт — в «полном каноне»
(§13/§21/§30 REFERENCE.md): journal v2, чистая физика с property-фаззингом, D&D,
a11y (axe 0), e2e, self-check в браузере. Не-ФИПИ опыты («бонусы ЛАБОСФЕРЫ») допустимы,
но помечаются `isFipi: false` и UI-бейджем.

### 2.1. Разрешённая неоднозначность (важно — фундамент эпика)

Сноска (2) СПЕЦ Прил. 2: «измерение жёсткости пружины, коэффициента трения скольжения,
**работы силы трения, силы упругости**». Фраза грамматически двусмысленна. Разрешено по
**КОДИФ §1.29** (дословно): перечень измерений содержит «…работы силы трения, **силы
упругости**…», а «работа силы упругости» фигурирует ОТДЕЛЬНО и ТОЛЬКО как «работы силы
упругости при подъёме груза неподвижным/подвижным блоком» → **комплект №6**.

**Вывод:** для комплекта №2 ФИПИ-опыт = **«измерение силы упругости» (F_упр одной точкой,
отсчёт динамометра)**. «Работа силы упругости» для пружины (наш `spring-work`) в ФИПИ
для kit-2 НЕ входит → это **бонус ЛАБОСФЕРЫ** (уже помечен в REFERENCE §30.4).

## 3. Авторитетный перечень опытов ФИПИ (дословно из Приложения 2)

Гранулярность — «измеримая/исследуемая единица», как в Кодификаторе. Составные исследования
(R от длины/сечения/ρ; F_тр от N / от рода поверхности; период маятника от массы / жёсткости)
считаются раздельно. Итого **44 опыта**.

## 5. Конвенции (Global Constraints — действуют на КАЖДУЮ волну)

Копируются в Global Constraints каждого плана волны.

1. **ФИПИ-якорь.** Каждый `*Experiment.ts` начинается docstring с дословной цитатой
   Приложения 2 / КОДИФ §1.29 + страница. Бонус → docstring `// ⚠️ БОНУС ЛАБОСФЕРА —
   НЕ ВХОДИТ В ФИПИ. Причина: …` и `isFipi: false`.
2. **Journal v2 (§21).** Новый опыт — только `renderJournalTable` + `JournalSpec` в
   `_shared-spa/.../journal/specs.ts`, `verifyRow`, `parseRu`, 3 режима записи
   (semi-auto / fully-manual / fully-auto) через `record-mode` с ключом `kit-<N>`.
   Кастом-рендереры допустимы только по паттерну §17.1 (поверх v2-инфры), не вместо неё.
3. **Чистая физика.** Модели — pure, DOM-free, в `src/physics/<id>/`, Vitest ≥95–100%
   coverage + property-фаззинг (§15.5: ≥12 категорий инвариантов, 50k+ итераций).
4. **Bootstrap (§14/§16).** Экран = `IScreen` (mount/unmount/saveState), оркестратор
   (Store + DragController + Journal), `template.html` с обязательными слотами
   (`stand-container`, `hint-bar`, `drag-overlay`, `record-mode-slot`, `journal-host`,
   `record-pending-slot`, `live-region`). Регистрация в `KitShell` + `Router(?screen=<id>)`.
5. **D&D через mouse.** Self-check тащит приборы только `page.mouse.move/down/up`
   (programmatic addItem не ловит overlay-dup §26). REST-state: drop-zones/pulse скрыты в покое.
6. **A11y.** axe 0 нарушений; роли/aria-live; клавиатура; `prefers-reduced-motion`;
   скрин-ридер не палит ответ (§10).
7. **SVG-приборы (§27/§28).** `lab-*`, shadow DOM, `svg[hidden]{display:none}`; eyelet ≤5%,
   уступы ≤2 ед., функц-деталь ≥15% viewBox.
8. **Каталог.** Обновить `kits.ts` (опыт + `isFipi` + прогресс по опытам ФИПИ).
9. **Гейты зелёные:** `npm run typecheck` / `test` / `lint` (0 err) / `build` + `selfcheck-<id>.mjs` PASS + ручной проход в браузере (reality-check скрином).
10. **Технологии:** TypeScript strict, Vite 6, vanilla Web Components (без фреймворков),
    npm workspaces. Дев-копия — `C:\dev\Inter_OGE` (не из `.business`: MAX_PATH).

## 8. Стратегия тестирования

Каждый опыт: pure-физика (Vitest 100% + фаззинг) → state-machine тест (happy-dom DOM
lifecycle) → e2e Playwright (drag через mouse, axe) → `selfcheck-<id>.mjs` (multi-state +
REST + 3 режима + overlay-dup) → ручной reality-check скрином. Гейты на уровне монорепо
(`--workspaces`) держатся зелёными после каждой волны.

## 9. Вне охвата (YAGNI)

- Мобильный sidebar <1024px и hover-анимация приборов на постер-стене (Phase 2 home).
- Реальное железо / BLE / экспорт результатов.
- Опыты, которых нет в ФИПИ И не одобрены отдельно как бонус.
- Химия (`chemistry/`) — отдельный трек, не часть этого эпика.
