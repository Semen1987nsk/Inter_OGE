> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Довести опыты **3.2 «Измерение мощности тока»** (P=U·I) и **3.3 «Измерение работы тока»** (A=U·I·t) до полного канона на уже существующем экране `measurements`, превратив его из одно-опытного в мульти-таск (переключатель задач A/B/C по образцу friction).

**Architecture:** Экран `measurements` (Фаза A, опыт 3.1) расширяется task-switcher'ом из трёх задач: **A «Сопротивление» (3.1, R=U/I)**, **B «Мощность» (3.2, P=U·I)**, **C «Работа тока» (3.3, A=U·I·t)**. Одна и та же топология цепи (источник→ключ→амперметр→резистор∥вольтметр) обслуживает все три задачи; различаются только активный SPEC журнала, формула, набор записываемых величин и (для C) управление временем t. Каждая задача ведёт свой набор записей (`measurement.task` + фильтрация журнала). Эталон паттерна — `kit-2-forces/src/screens/friction` (`#steps` как переключатель `data-task`, `setActiveTask`, `#currentSpec()`, `#refreshTaskStepper()`, per-task формула).

## Решения дизайна Фазы B (зафиксировано)

1. **Task-switcher = repurpose `#steps`.** Текущие `#steps` (рабочие шаги 1–4 «Соберите цепь / Замкните ключ / …») заменяются на 3 вкладки задач `data-task` (`A-resistance`/`B-power`/`C-work`), как `#steps` во friction. Пошаговое руководство уже несёт `#hint-bar` (HintEngine) — дублирующие «шаги» убираем. Стили `.step[data-state='active']` переиспользуются как есть.
2. **Выбор резистора — физический (drag), не тумблер.** Спека упоминает «переключатель резистор R1/R2/R3» — реализуем как ТРИ перетаскиваемых карточки (R1/R2/R3) в панели оборудования (принцип «полная имитация реального мира»: резистор вставляют в цепь, а не переключают). Добавляем карточку **R3 (8,2 Ом)** к существующим R1/R2. Журнал фиксирует фактический вариант в meta-колонке `resistor`. Per-task подсказка рекомендует ФИПИ-резистор (3.1→R1, 3.2→R3, 3.3→R2), но физика работает с любым.
3. **Измерения тегируются задачей + журнал фильтруется по активной задаче.** `measurement.task: CircuitTaskId`. В отличие от friction (общий список без фильтра), здесь каждый опыт (3.1/3.2/3.3) — отдельный ФИПИ-опыт, и t существует только в C → показываем журнал/счётчик/результат ТОЛЬКО для записей активной задачи. Обоснование: запись «мощность» не имеет осмысленного t; смешение под WORK-спекой дало бы пустые ячейки.
4. **Время t (опыт 3.3) — пресет + анимированный секундомер, авто-доводка до точного t.** В задаче C появляется `#time-control`: сегмент-кнопки **30 / 60 / 120 с** (по умолчанию 60) + readout-«секундомер». При замыкании ключа в задаче C секундомер анимированно идёт 0→t (ускоренно ×20, ~3 с реального времени; `prefers-reduced-motion` → мгновенно) и авто-останавливается на ТОЧНОМ пресете t. Записанное t = пресет (детерминированно → чистые тесты и журнал). Программный API `setTimeS(t)` + `recordMeasurement()` НЕ зависят от анимации (тесты/selfcheck выставляют t и пишут напрямую; анимация — косметика и UI-гейт для pending-плашки). RAF снимается в reset/destroy/смене задачи.
5. **CircuitModel не трогаем** — `power`/`workOfCurrent` готовы.

Методы:
```ts
  #startStopwatch(): void {
    if (!this.#refs.stopwatchReadout) return;
    this.#stopStopwatch();
    const target = this.#store.get().timeS;
    const reduced =
      typeof matchMedia === 'function' && matchMedia('(prefers-reduced-motion: reduce)').matches;
    if (reduced || typeof requestAnimationFrame !== 'function') {
      this.#refs.stopwatchReadout.textContent = `t = ${target} с`;
      return;
    }
    const ACCEL = 20; // 60 c → 3 c реального времени
    this.#stopwatchStart = performance.now();
    const tick = (now: number) => {
      const simElapsed = ((now - this.#stopwatchStart) / 1000) * ACCEL;
      const shown = Math.min(target, Math.round(simElapsed));
      if (this.#refs.stopwatchReadout) this.#refs.stopwatchReadout.textContent = `t = ${shown} с`;
      if (shown >= target) { this.#stopwatchRaf = null; return; }
      this.#stopwatchRaf = requestAnimationFrame(tick);
    };
    this.#stopwatchRaf = requestAnimationFrame(tick);
  }

  #stopStopwatch(): void {
    if (this.#stopwatchRaf !== null) {
      cancelAnimationFrame(this.#stopwatchRaf);
      this.#stopwatchRaf = null;
    }
  }
```
